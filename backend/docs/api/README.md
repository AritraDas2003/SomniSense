## Conventions (all endpoints)

- **Base URL (local):** `http://localhost:8080/api/v1`
- **Login:** a server-side session cookie plus a CSRF header. Use axios with `withCredentials: true` and
  `withXSRFToken: true` (see [AUTH.md](AUTH.md)). Allowed browser origins: `http://localhost:5173` and
  `http://127.0.0.1:5173`.
- **Roles:** `ADMIN` and `OPERATOR`. The backend enforces them on every request, so hiding a button is
  only cosmetic.
- **Success responses** are plain JSON with no wrapper. Creating something returns `201` plus a `Location` header.
- **Errors** always use the same shape. Branch on `code`, never on `message`. Every response carries an
  `X-Correlation-Id` header.
- **Lists** look like `{content, page, size, totalElements, totalPages}`. `page` starts at 0. `size` is at
  most 100 (readings: at most 1000).
- **Times** are ISO-8601 **UTC** (`...Z`). `dateOfBirth` is a plain date (`YYYY-MM-DD`).
- **IDs** are UUID strings. Human-readable codes are generated by the backend: `PT-…` (patient),
  `DEV-…` (device, unless staff typed one), `SES-yyyyMMdd-…` (session).
- **Enums** are UPPER_CASE strings:

  | Enum | Values |
  |---|---|
  | role | `ADMIN`, `OPERATOR` |
  | sourceType / deviceType | `PHYSICAL`, `SIMULATED` |
  | patient status | `ACTIVE`, `INACTIVE` |
  | gender | `FEMALE`, `MALE`, `OTHER`, `UNDISCLOSED` |
  | enrollmentStatus | `PENDING`, `ENROLLED`, `SETUP_REQUIRED` |
  | connectivityStatus | `CONNECTED`, `STALE`, `DISCONNECTED`, `UNKNOWN` |
  | session status | `ACTIVE`, `ENDED`, `CANCELLED` |
  | predictedClass | `APNEA_EVENT`, `NORMAL` |
  | predictionStatus | `COMPLETED`, `NEEDS_REVIEW`, `REJECTED`, `ERROR` |
  | inputQualityStatus | `VALID`, `DEGRADED`, `REJECTED` |

- **`null` means "no value".** In particular, `spo2` and `heartRate` are `null` during a dropout. Show a gap
  or "no reading", **never 0**.
- **Repeating an action is safe:** assign, start session, end, release and deactivate return the current
  state when they have already been done.

## First vertical slice: suggested integration order

| Step | UI | Calls |
|---|---|---|
| 1 | App start / login (C01–C05, C79–C80) | `GET /auth/csrf` → `GET /auth/me` (401 = show login) → `POST /auth/login` → `POST /auth/logout` |
| 2 | Dashboard / patient table (C14–C23) | `GET /patients?q=&sourceType=&status=&page=&size=&sort=&direction=`. Each row has `currentDevice` (with `connectivityStatus`), `activeSession` and `latestReading` |
| 3 | Add patient (C24–C31) | `POST /patients` → show the returned `patientCode` |
| 4 | Devices + assignment (C31–C42) | `GET/POST /devices`, `POST /device-assignments` (on `409 DEVICE_ALREADY_ASSIGNED` / `PATIENT_ALREADY_HAS_DEVICE`, confirm, then resend with `replaceExisting: true`) |
| 5 | Session controls (C43, C53) | `POST /sessions`, `POST /sessions/{id}/end` or `/cancel` |
| 6 | Live monitoring (C44–C51) | poll `GET /sessions/{id}/readings/latest` (for example every 5 s) plus `GET /sessions/{id}/readings?from=&to=` for the charts |
| 7 | Manage staff (Admin) | `/users…` and `POST /auth/password` |

## Testing it yourself

Use the Postman collection in [`../../postman/`](../../postman/) (see the backend README). It runs the
whole slice above in order, with checks on every request.

## Safety wording (all screens)

This is an educational monitoring prototype.

- `CONNECTED` / green means **data is arriving**, not that the patient is fine.
- Readings from `SIMULATED` devices must always carry a visible **SIMULATED** label.
- Model output (when it arrives) means "Possible event — review", never a diagnosis.
