# SomniSense API — Monitoring Sessions

**Status:** Implemented and tested (Stage 8, 2026-11-21). The frontend may replace its session start, stop
and status mocks. Session cookie + CSRF header as in [AUTH.md](AUTH.md). Errors follow [ERRORS.md](ERRORS.md).

**Roles:** `ADMIN` and `OPERATOR` can start, end, cancel and view sessions.

A *monitoring session* is one period of monitoring a patient with their assigned device. It is not the same
thing as the login session.

## Lifecycle

```
            start                  end
  (none) ─────────► ACTIVE ─────────────► ENDED       finished normally; its readings are the session's data
                       │
                       └────────────────► CANCELLED   started by mistake or aborted; readings kept, but marked
                           cancel                     as belonging to a cancelled session
```

- `ENDED` and `CANCELLED` are **final**.
- Repeating the same action is safe: ending an ended session returns `200` with no change.
- Switching between the two final states (end after cancel, or cancel after end) returns
  `409 INVALID_SESSION_TRANSITION`.
- `startedBy` / `endedBy` always come from the logged-in user, and all timestamps come from the server clock
  (UTC). Clients can never set them.

## Rules for starting

| Rule | Error if broken |
|---|---|
| The patient exists | `404` |
| The patient is ACTIVE | `409 PATIENT_NOT_ACTIVE` |
| The patient has a device assigned. The backend uses that assignment | `409 NO_ACTIVE_ASSIGNMENT` |
| If `deviceAssignmentId` is sent, it must be the patient's **current** assignment (protects against a stale screen) | `409 ASSIGNMENT_MISMATCH` |
| The device is still active and `ENROLLED` | `409 DEVICE_NOT_AVAILABLE` |
| At most one ACTIVE session per patient or assignment. **Starting again while one is ACTIVE returns that session with `200`**, so a double click is safe | `409 SESSION_ALREADY_ACTIVE` (only in edge cases) |

**Effect on assignments:** while a session is ACTIVE, releasing or reassigning its device returns
`409 SESSION_ACTIVE`, for example *"Patient PT-L6NP4WLM is being monitored (session SES-20261121-68KSW8);
end the session first."* End the session first.

**Simultaneous requests:** the patient row and the assignment row are locked while a session starts. If
"Start" and "Release" are pressed at the same moment, exactly one of them succeeds, and there is never an
active session on a released device. The database (V3 partial unique indexes) also refuses a second ACTIVE
session.

## Endpoints

| Method | Path | Body | Success | Typical errors |
|---|---|---|---|---|
| POST | `/api/v1/sessions` | `{"patientId":"...","deviceAssignmentId":"..."}` (`deviceAssignmentId` optional) | `201` Session + `Location` (new), **or** `200` (already running) | see the table above, `400 VALIDATION_FAILED` |
| POST | `/api/v1/sessions/{id}/end` | — | `200` Session (`ENDED`) | `404`, `409 INVALID_SESSION_TRANSITION` |
| POST | `/api/v1/sessions/{id}/cancel` | — | `200` Session (`CANCELLED`) | `404`, `409 INVALID_SESSION_TRANSITION` |
| GET | `/api/v1/sessions/{id}` | — | `200` Session | `404` |
| GET | `/api/v1/sessions?patientId=&status=&startedFrom=&startedTo=&page=&size=` | — | `200` Page of Session, newest first | `400` |

List filters:

- `status` is `ACTIVE`, `ENDED` or `CANCELLED`.
- `startedFrom` (inclusive) and `startedTo` (exclusive) are ISO-8601 UTC timestamps, for example
  `2026-11-21T00:00:00Z`. `startedFrom` must be before `startedTo`.
- `size` is 1–100.

### Session

```json
{
  "id": "3cb7635e-e802-40c3-87dd-0f86c511cbd3",
  "sessionCode": "SES-20261121-68KSW8",
  "status": "ACTIVE",
  "sourceType": "SIMULATED",
  "patientId": "...",
  "patientCode": "PT-L6NP4WLM",
  "deviceAssignmentId": "...",
  "deviceId": "...",
  "deviceCode": "DEV-H2FP2ABH",
  "startedBy": "<staff user id>",
  "startedAt": "2026-11-21T14:00:13.416408Z",
  "endedBy": null,
  "endedAt": null,
  "durationSeconds": 0
}
```

| Field | Notes |
|---|---|
| `sessionCode` | `SES-` + start date (UTC, `yyyyMMdd`) + `-` + 6 random characters; generated by the backend |
| `sourceType` | the device's type. Show a persistent **SIMULATED** label when it is `SIMULATED` |
| `durationSeconds` | start → end, or start → now while `ACTIVE` |

## Where sessions also appear

`GET /patients` (each row) and `GET /patients/{id}` include `activeSession`:
`{ "sessionId", "sessionCode", "startedAt" }`, or `null` when the patient is not being monitored.
